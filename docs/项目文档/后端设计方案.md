## 一、目的和设计要求

### 1.1 项目目的

本项目旨在为 War Thunder（战争雷霆）游戏玩家打造一个集**论坛交流**、**教程分享**、**内容管理**于一体的中文社区平台。后端系统作为整个平台的核心支撑，承担用户认证、数据持久化、业务逻辑处理、内容审核等关键职责，为前端 JSP 页面提供稳定、高效、安全的数据服务。

#### 1.1.1 核心目标

| 目标维度 | 具体描述 |
|---------|---------|
| **用户体验** | 支持用户注册登录、发帖评论、教程浏览等核心操作，响应及时，交互流畅 |
| **内容生态** | 构建论坛帖子 + 图文教程 + 视频教程三位一体的内容体系，支持分类浏览与搜索 |
| **管理运维** | 提供完善的管理员后台，实现用户管理、内容审核、资源管控 |
| **安全可靠** | 保障用户数据安全，防止 SQL 注入、XSS 攻击，权限控制严格 |

#### 1.1.2 业务价值

- **社区凝聚**：将分散在各平台的 War Thunder 玩家汇聚到统一社区
- **知识沉淀**：通过教程中心系统化整合战术攻略、载具测评等优质内容
- **互动交流**：提供论坛发帖、楼中楼评论等社交功能，促进玩家互动

### 1.2 设计要求

#### 1.2.1 功能需求

后端系统需覆盖以下五大功能模块：

| 模块 | 子功能 | 关键接口/Controller |
|------|--------|---------------------|
| **用户系统** | 用户注册、登录验证、个人信息编辑、密码修改、权限分级（管理员/版主/普通用户） | `user_controller`、`register_controller`、`ProfileController` |
| **论坛功能** | 帖子列表、帖子详情、发布帖子、编辑帖子、删除帖子、多图上传 | `PostController`、`PostDetailController`、`PublishPostController`、`DeletePostController` |
| **评论系统** | 发表评论、楼中楼回复、删除评论 | `CommentController`、`DeleteCommentController` |
| **教程中心** | 图文教程 CRUD、视频教程管理、分类筛选（地图/载具/弱点）、浏览量统计 | `TutorialArticleController`、`TutorialArticleDetailController`、`VideoController`、`VideoPublishController` |
| **管理后台** | 用户管理、内容审核、帖子/评论/视频管理、全站搜索 | `AdminController`、`ReviewController`、`SearchController` |

#### 1.2.2 非功能需求

| 类别 | 要求指标 | 说明 |
|------|---------|------|
| **性能要求** | 页面首次加载 ≤ 3s<br>数据库查询响应 ≤ 1s<br>支持 ≥ 50 并发用户 | 依赖外部 Bilibili 服务的响应时间除外 |
| **安全要求** | 密码加密存储（MD5）<br>PreparedStatement 防 SQL 注入<br>XSS 跨站脚本防护<br>管理员功能身份验证 | 见 [DBHelper.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/db/DBHelper.java) 中 PreparedStatement 使用 |
| **兼容性要求** | Chrome 80+、Firefox 75+、Edge 80+、Safari 13+<br>支持移动端浏览器<br>分辨率 ≥ 1024×768 | 前端 JSP 页面需适配 |
| **可用性要求** | 界面布局清晰、导航明确<br>错误提示友好、操作反馈及时<br>整体风格统一 | 前后端协同保障 |
| **可维护性** | 代码分层清晰（Controller/Service/DAO/Model）<br>命名规范一致<br>关键逻辑有注释说明 | 详见代码结构 |

#### 1.2.3 数据设计要求

- 数据库采用 MySQL 8.0，字符集 utf8mb4，支持完整 Unicode（含 emoji）
- 核心表 5 张：`user`、`post`、`comment`、`tutorial_articles`、`tutorial_videos`
- 建立适当的外键约束和索引，保证数据一致性和查询效率
- 支持软删除/状态字段（`status`），避免物理删除导致的数据丢失

#### 1.2.4 架构设计要求

采用经典 **MVC 三层架构**：

```
┌─────────────────────────────────────────┐
│         Controller 控制层（Servlet）    │  ← 接收请求，参数校验，响应返回
├─────────────────────────────────────────┤
│            Service 业务逻辑层           │  ← 业务封装，事务管理（待扩展）
├─────────────────────────────────────────┤
│              DAO 数据访问层             │  ← SQL 执行，结果封装
├─────────────────────────────────────────┤
│             DBHelper 工具类             │  ← JDBC 连接，资源管理
├─────────────────────────────────────────┤
│              MySQL 数据库               │  ← 数据持久化存储
└─────────────────────────────────────────┘
```

### 2.2 系统架构

#### 2.2.1 整体架构

系统采用 **B/S 架构**（浏览器/服务器模式），后端基于 Java Web 技术栈，前端使用 JSP + HTML/CSS/JS。请求响应流程如下：

```
浏览器（JSP页面）
    │
    │ HTTP 请求（GET/POST）
    ▼
Servlet 控制器（@WebServlet）
    │
    │ 调用业务方法
    ▼
Service 业务层（user_service）
    │
    │ 调用数据访问方法
    ▼
DAO 数据访问层（user_dao）
    │
    │ 执行 SQL
    ▼
DBHelper（JDBC 封装）
    │
    ▼
MySQL 数据库（mydata）
```

#### 2.2.2 分层设计详解

**1. Model 层（模型层）**

位置：`src/main/java/model/`

包含 6 个实体类，与数据库表一一对应：
- [user_model.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/user_model.java) — 用户模型
- [PostModel.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/PostModel.java) — 帖子模型（含审核状态、多图片字段）
- [CommentModel.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/CommentModel.java) — 评论模型（支持楼中楼 parent_id）
- [TutorialArticleModel.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/TutorialArticleModel.java) — 教程文章模型
- [VideoModel.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/VideoModel.java) — 视频教程模型
- [ArticleModel.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/model/ArticleModel.java) — 文章通用模型

每个 Model 包含：私有字段 + getter/setter + 构造方法 + 辅助方法（如 `isActive()`、`hasImages()`、状态文本转换等）。

**2. DAO 层（数据访问层）**

位置：`src/main/java/dao/user_dao.java`

封装所有数据库操作，通过 [DBHelper](file:///d:/Helloworld/JAVA/myhomework/src/main/java/db/DBHelper.java) 执行 SQL。主要方法包括：
- 用户：`find_user_name_password`、`findUserByEmail`、`insertuser`、`updateUser` 等
- 帖子：`findPostById`、`findAllPosts`、`insertPost`、`updatePost`、`deletePost` 等
- 评论：`findCommentsByPostId`、`insertComment`、`deleteComment` 等
- 教程：文章/视频的增删改查、分类查询、浏览量递增等
- 搜索：关键词模糊查询（LIKE）

**3. Service 层（业务逻辑层）**

位置：`src/main/java/service/user_service.java`

作为 Controller 与 DAO 之间的桥梁，封装业务逻辑。当前项目中 Service 层主要为 DAO 的直接封装，预留了事务管理、缓存、日志等扩展点。

#### 2.2.3 数据库设计

核心 5 张表结构概览：

| 表名 | 用途 | 关键字段 | 索引 |
|------|------|---------|------|
| `user` | 用户表 | id, username, password, email, role, avatar | email（唯一） |
| `post` | 论坛帖子 | id, title, content, user_id, status, image1~6, create_time | user_id |
| `comment` | 帖子评论 | id, post_id, user_id, content, parent_id, create_time | post_id, user_id, parent_id |
| `tutorial_articles` | 教程文章 | id, title, content, category, user_id, view_count, image1~6 | user_id, category |
| `tutorial_videos` | 教程视频 | id, bvid, title, description, thumbnail_url, category, view_count, likes | category |

外键约束：
- `comment.post_id` → `post.id`（级联删除）
- `comment.user_id` → `user.id`（级联删除）
- `comment.parent_id` → `comment.id`（级联删除，支持楼中楼）
- `post.user_id` → `user.id`（级联删除）
- `tutorial_articles.user_id` → `user.id`（级联删除）

### 2.3 关键功能实现方案

#### 2.3.1 用户认证与权限

- **登录机制**：基于 HttpSession，登录成功后将用户名存入 `session.setAttribute("loginUser")`
- **权限分级**：用户表 `role` 字段（0=管理员，1=普通用户），扩展支持版主角色
- **权限校验**：每个 Controller 在处理请求前检查 Session 中是否有登录用户
- **密码安全**：MD5 加密存储（可升级为 BCrypt）

#### 2.3.2 文件上传

- 使用 Servlet 3.0 `@MultipartConfig` 注解处理文件上传
- 单文件最大 50MB，请求最大 100MB
- 文件命名：UUID 随机字符串 + 原扩展名，避免重名冲突
- 存储路径：`static/upload/` 目录下按业务分类（post、article 等）

#### 2.3.3 评论楼中楼

- `comment` 表通过 `parent_id` 字段自关联实现多级回复
- `parent_id = NULL` 表示一级评论
- 查询时按 `parent_id` 分组构建评论树
- 支持级联删除（删除父评论自动删除所有子评论）

#### 2.3.4 内容审核机制

- 帖子/文章/视频均包含审核状态字段（待审核/已通过/已拒绝）
- 不同角色发布内容走不同审核流程：
  - 普通用户：全部需审核
  - 版主：帖子/文章直接通过，视频需审核
  - 管理员：全部直接通过
- 审核意见字段 `reviewMessage` 记录拒绝原因

#### 2.3.5 教程视频集成

- 通过 Bilibili BV 号集成视频教程
- 存储视频缩略图 URL、标题、描述、分类等元数据
- 播放量实时统计（每次访问 +1）
- 支持按分类（maps/vehicles/weakspots）筛选

#### 2.3.6 搜索功能

- 基于 MySQL `LIKE` 模糊查询
- 支持帖子标题和内容关键词搜索
- 管理员支持用户搜索（用户名/邮箱）
- 搜索结果分页展示

### 2.4 安全方案

| 安全威胁 | 防护措施 | 实现位置 |
|---------|---------|---------|
| SQL 注入 | 使用 PreparedStatement 预编译语句，参数化查询 | [DBHelper.java](file:///d:/Helloworld/JAVA/myhomework/src/main/java/db/DBHelper.java#L95-L115) |
| XSS 攻击 | 前端 JSP 输出时使用 `<c:out>` 标签或 JSTL 转义 | 各 JSP 页面 |
| 越权访问 | Session 登录校验 + 作者权限检查（只能编辑自己的内容） | 各 Controller |
| 密码泄露 | MD5 单向加密存储，不明文存储密码 | 注册/登录逻辑 |
| 文件上传攻击 | 文件类型校验、UUID 重命名、限制文件大小 | 上传相关 Controller |

### 3.5 风险与应对

| 风险项 | 可能性 | 影响 | 应对策略 |
|--------|--------|------|---------|
| 需求变更导致范围扩大 | 中 | 中 | 严格控制变更流程，优先核心功能，非核心功能延后到后续迭代 |
| 技术难点卡壳（如视频集成） | 中 | 低 | 提前调研技术方案，预留缓冲时间，准备简化备选方案 |
| 性能瓶颈（查询慢） | 低 | 中 | 第10次迭代专门进行SQL优化和索引检查，必要时引入缓存 |
| 安全漏洞 | 低 | 高 | 使用 PreparedStatement 防注入，密码加密，输入校验，第10次迭代安全审查 |
| 时间延误 | 低 | 高 | 每个迭代设置明确目标，提前识别关键路径任务，必要时加班赶工 |
| 测试遗漏 | 中 | 中 | 第10次迭代进行全模块回归测试，编写测试用例文档 |

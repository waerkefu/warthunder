## 第1次实践课 — 2026-05-26 — 需求分析与数据库设计

### 一、实践目标

1. 完成项目需求分析，明确系统功能边界
2. 设计数据库表结构，建立 ER 图
3. 编写建表 SQL 脚本

通过查阅 War Thunder 游戏社区现状和类似论坛系统的设计方案，明确了本系统的五大核心功能模块：

- **用户系统**：用户注册、登录、个人信息管理、权限分级

- **管理后台**：用户管理、内容审核、帖子/评论/视频管理、全站搜索

### 三、遇到的问题及解决方法

**问题1：需求分析阶段对部分功能边界不够清晰**

- **问题描述**：在设计用户权限系统时，对管理员、版主和普通用户的权限划分不够明确，导致初期表结构设计存在冗余字段（如为版主单独设计了一张表）。
- **解决方法**：通过查阅类似项目的权限设计方案，重新梳理了角色权限规则，决定使用单一的 role 字段来区分不同角色（0=管理员，1=普通用户，2=版主），取消了单独的版主表，简化了表结构设计。

**问题2：外键约束设计不合理**

- **问题描述**：初期设计的外键约束没有考虑级联删除的需求，导致删除用户时其发布的帖子和评论无法自动删除。
- **解决方法**：在创建外键约束时添加了 `ON DELETE CASCADE` 选项，确保删除用户、帖子时关联的数据能够自动级联删除，保证数据一致性。

3. 理解了外键约束和级联操作的原理和应用场景
4. 认识到良好的数据库设计对后续开发的重要性

### 三、遇到的问题及解决方法

**问题1：数据库连接时出现中文乱码**

- **问题描述**：向数据库插入中文数据时，数据显示为乱码（???）。
- **解决方法**：
  1. 在数据库连接 URL 中添加了 `?serverTimezone=UTC&characterEncoding=utf8` 参数
  2. 在 web.xml 中配置了字符编码过滤器：
     ```xml
     <filter>
         <filter-name>encodingFilter</filter-name>
         <filter-class>org.springframework.web.filter.CharacterEncodingFilter</filter-class>
         <init-param>
             <param-name>encoding</param-name>
             <param-value>UTF-8</param-value>
         </init-param>
         <init-param>
             <param-name>forceEncoding</param-name>
             <param-value>true</param-value>
         </init-param>
     </filter>
     <filter-mapping>
         <filter-name>encodingFilter</filter-name>
         <url-pattern>/*</url-pattern>
     </filter-mapping>
     ```
  3. 在每个 Servlet 中设置了 `request.setCharacterEncoding("UTF-8")` 和 `response.setContentType("text/html;charset=UTF-8")`

**问题2：MySQL JDBC 驱动加载失败**

- **问题描述**：运行项目时抛出 `ClassNotFoundException: com.mysql.cj.jdbc.Driver` 异常。
- **解决方法**：检查 pom.xml 文件，确认 MySQL 驱动依赖配置正确：
  ```xml
  <dependency>
      <groupId>mysql</groupId>
      <artifactId>mysql-connector-java</artifactId>
      <version>8.0.25</version>
  </dependency>
  ```
  然后重新执行 `mvn clean install` 命令下载依赖。

### 三、遇到的问题及解决方法

**问题1：登录时 Session 设置后无法获取**

- **问题描述**：登录成功后设置了 Session，但在其他页面获取时返回 null。
- **解决方法**：检查发现是因为登录页面使用了表单提交但没有正确处理 Session 的创建。修改了登录控制器的逻辑：
  ```java
  HttpSession session = request.getSession();
  session.setAttribute("loginUser", username);
  session.setAttribute("userId", userId);
  ```
  确保使用 `request.getSession()` 获取正确的 Session 对象。

**问题2：MD5 密码加密结果不一致**

- **问题描述**：注册时对密码进行了 MD5 加密，但登录时验证失败，因为两次加密结果不一致。
- **解决方法**：检查发现是因为密码输入框的 name 属性与后台获取的参数名不一致。统一了前后端的参数命名，确保密码能够正确传递和加密。

### 三、遇到的问题及解决方法

**问题1：头像上传时文件路径处理不正确**

- **问题描述**：头像上传成功，但在页面上无法显示，检查发现数据库中存储的路径不正确。
- **解决方法**：修改了文件上传路径的处理逻辑：
  ```java
  String uploadPath = getServletContext().getRealPath("") + File.separator + UPLOAD_DIR;
  String filePath = uploadPath + File.separator + newFileName;
  part.write(filePath);
  return UPLOAD_DIR + "/" + newFileName;
  ```
  使用 `getServletContext().getRealPath()` 获取正确的服务器路径，并正确拼接文件相对路径存储到数据库中。

**问题2：权限验证逻辑过于复杂**

- **问题描述**：在多个控制器中重复编写了权限验证代码，导致代码冗余且维护困难。
- **解决方法**：将权限验证逻辑抽取为公共方法，放在 user_service 中：
  ```java
  public boolean hasPermission(String username, int requiredRole) {
      // 根据用户名查询用户角色并进行判断
  }
  ```
  这样各个控制器只需调用这个方法即可完成权限验证。

### 三、遇到的问题及解决方法

**问题1：多图上传时部分图片无法正确保存**

- **问题描述**：上传6张图片时，部分图片无法保存到服务器，返回上传失败。
- **解决方法**：检查发现有两个问题：
  1. 文件大小限制：配置了 `@MultipartConfig` 注解，设置了合理的文件大小限制：
     ```java
     @MultipartConfig(
         fileSizeThreshold = 1024 * 1024 * 5,
         maxFileSize = 1024 * 1024 * 50,
         maxRequestSize = 1024 * 1024 * 100
     )
     ```

  ```java
  String visitedKey = "visited_tutorial_" + tutorialId;
  ```

- **问题描述**：管理员可以查看所有用户的密码，存在安全风险。
- **解决方法**：
  1. 确保密码使用 MD5 加密存储，管理员看到的是加密后的密码
  2. 添加权限验证，只有管理员（role=0）可以查看密码，版主（role=2）没有此权限
  3. 在用户管理页面中，密码列仅对管理员显示

### 四、实践收获

1. 掌握了管理员后台功能的开发方法
2. 学会了内容审核机制的实现
3. 理解了基于角色的权限管理的重要性
4. 掌握了后台管理页面的设计和开发技巧

- **问题描述**：在本地开发环境中数据库连接正常，但部署到服务器后连接失败。
- **解决方法**：检查了以下配置：
  1. 确认数据库服务已启动
  2. 确认数据库连接 URL 中的主机地址正确
  3. 确认数据库用户名和密码正确
  4. 确认服务器防火墙允许访问数据库端口
  5. 修改了数据库连接配置，使用服务器的 IP 地址而非 localhost
